## 一、这件事在做什么（30 秒版）

我们把 **近半年学练机发版** 和 **用户原声（工单 + 反馈）** 串成一条线，回答三个问题：

1. **发了什么用户能感知的功能？**（发版项台账）
2. **发版前用户有没有提过相关诉求？**（用户原声关联）
3. **要不要主动告诉这些用户「你们提的问题我们做了」？**（触达清单）

这不是替代日常工单处理，而是 **发版后的复盘与主动触达机制**。

## 五、匹配规则（对外怎么讲）

**只对台账里「用户可感知 = 是」的 13 项做关联**，其余 95 项不参与。

**在两类数据里搜：**

- **JUST 工单**（3081 条）：问题标题、描述、分类
- **Cupid 用户反馈**（3983 条）：反馈正文、分类、设备

**怎么算命中：**

1. 根据发版项名称 +「用户价值一句话」+ 功能关键词表，生成一组搜索词  
   （例：名校专区、AI精准复习、口算、错题本、卡顿、寒假计划…）
2. 工单或反馈正文里 **只要出现其中任意一个词**，就算可能相关
3. 命中词越多，**匹配分**越高；达到门槛即进入关联表，**不设条数上限**
4. 导出结果默认 **「待确认」**——是关键词召回，不是 AI 语义判断，需要人工看摘要和匹配词再确认

**举例：**

- 反馈写「寒假预复习计划什么时候有」→ 关联「备考计划支持跨册次」
- 反馈写「阶段测找不到试卷」→ 可能关联「名校专区」
- 反馈只写「充不进电」→ 不会关联到「作文批改」

## 七、怎么触达用户

**谁能触达：**  
主要是 Cupid **用户反馈**里有 **userId** 的用户（当前候选约 **898** 人）。  
**工单**一般无直接联系方式，用作「用户提过这类问题」的佐证，不适合批量私信。

**推荐流程：**

```
Sheet2 确认关联 → 标记「需要触达=是」 → Sheet3 写话术 → Cupid/客服渠道联系 → 回填「已触达」
```

**触达优先级建议：**

1. 匹配分高 + 诉求与发版项高度一致  
2. 反馈时间较近（发版前后 3 个月内更佳）  
3. 同一用户多条诉求可合并一次触达  

**话术模板（按发版项改括号内容）：**

> 您好，感谢您此前通过反馈提到「【用户原话摘要】」。  
> 我们在 **【版本号，如 2.73.0】**（【发版日期】）已上线 **【功能名，如备考计划支持跨册次】**，【一句话价值，如支持高中备考一次选择多册次内容】。  
> 您可以在设备 **【入口路径，如：首页 → 备考 / 阶段测】** 体验。如仍有问题欢迎继续反馈，我们会持续优化。

**分场景示例：**

| 发版项 | 可引用用户原声 | 触达要点 |
|--------|----------------|----------|
| 备考计划支持跨册次 | 「寒假/期末复习计划」「跨年级备考」 | 强调多册次一次选 |
| 名校专区 | 「找不到好试卷」「阶段测」 | 强调试卷筛选新入口 |
| 口算错题本同步 | 「口算错题」「多账号」 | 强调错题已可跨账号同步 |
| 反应慢优化 | 「卡顿」「反应慢」「重影」 | 说明性能优化 + 刷新模式设置 |
| AI助手外显 | 「找不到小猿」「不知道助手能干嘛」 | 说明入口更显眼、能做什么 |

## 八、风险与说明（汇报时可主动讲）

1. **关联数是召回量，不是确认量**——5597 条需人工筛，实际相关会少很多。  
2. **反馈数据有缺口**——6 月 Cupid 导出不完整，可能漏关联近期原声。  
3. **泛词误关联**——如「小猿」「试卷」会拉入大量弱相关，需人工剔除。  
4. **触达不是必做全量**——建议先小批量试点（如每发版项 10–20 人），看回复率再扩。  
5. **与日常工单闭环独立**——本机制侧重「发版价值外化」，不替代 JUST 工单处理 SLA。
